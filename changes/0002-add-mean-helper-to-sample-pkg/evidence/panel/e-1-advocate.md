## Verdict
Uphold only the narrow flag (CLAUDE.md Layout omits `mean`); reject the "second occurrence →
Things Claude gets wrong" clause and the proposal line it produced.

## The case against
1. The repetition premise is false under the project's own definition. `framework/plugin/review/findings.py: update_seen` states it plainly: "two occurrences inside one change are one mistake being reviewed twice, not the pattern the CLAUDE.md line is for", and `repeated` only fires when `first_change != change_id`. The finding cites "already twice within change 0002's own review history" — `changes/.review-seen.json` shows `cc24ed45` and `3c842277` both with `first_change == last_change == "0002"`: one finding reworded across two review passes, which minted a second signature rather than a second occurrence. The 0001 entries (`f608c482`, `182179ac`) are different signatures again, so REVIEW.md's "same finding across reviews" is not met on the mechanism the project uses to decide sameness.
2. The line already written is not the artifact the rule asks for. `changes/0002-add-mean-helper-to-sample-pkg/evidence/claude-md-proposals.md` holds the finding summary verbatim with the `(change 0002; the owner edits CLAUDE.md)` suffix — i.e. it came from `claude_md_first_time_lines` (HANDOFF 6(f)), not from `claude_md_lines(repeated)`. Pasted under "Things Claude gets wrong" it gives the guardrail file an 80-word self-referential paragraph citing `.review-seen.json` and line numbers 22/23 that goes stale the moment Layout is fixed, while still not adding `mean` to Layout — the one thing intent.md asked for ("the Layout section of CLAUDE.md (a one-line update, proposed in the PR for the owner)").
3. The claimed lesson is the designed workflow, not a mistake. CLAUDE.md line 22 already names `percent`, so after 0001 the owner did apply the update: the loop works. "Things Claude gets wrong" is for behaviour a future run can change; no run may edit CLAUDE.md (intent Constraints; CLAUDE.md "Never edit ... CLAUDE.md"), so this entry is unactionable text in a file CLAUDE.md itself says to keep under a page.
4. Blast radius of accepting it: `gate/checks.py: check_findings` blocks phase (e) on any open Important finding, and this one is anchored at a file the run is forbidden to touch. Blessing the enlarged version re-creates exactly the deadlock HANDOFF 6(f) was written to remove, and every future public function reproduces it.

Instead: settle the item as the narrow flag, unfixable in-run and therefore panel-settled (not blocking), with the proposal rewritten as the concrete Layout one-liner naming `mean` alongside `add`, `divide`, `percent` (and the `__init__.py` re-export line).

I would accept the obvious resolution if the same signature were recorded by a change other than 0002 so `repeated` genuinely fires, or if the proposed entry were phrased as something a run can act on — e.g. "when a change adds a public function to `sample_pkg`, put the CLAUDE.md Layout line in the build PR body" — which is a real, repeated miss (0001's review found PR #7's body carried no such text).
